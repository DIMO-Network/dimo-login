# Languages (i18n)

The login UI is available in English, Spanish, Japanese, Simplified Chinese (`zh-Hans`) and Traditional Chinese (`zh-Hant`, written for Taiwan). Copy lives in
`src/i18n/locales/` (`en.ts`, `es.ts`, `ja.ts`, and the Chinese files). Everything else in the app refers to it by key.

## Which language is shown

English is always loaded. Spanish and Japanese copy loads when the language is chosen; if it can't load, the current language stays.

The first match wins (`src/i18n/language.ts`):

1. **The user's pick.** Whatever they last chose in the language switcher is remembered per app (`dimo_login_language_<clientId>` in localStorage).
2. **The app's configured `language`.** This can come from:
   - the SDK option (`initializeDimoSDK({ options: { language: 'ja' } })`),
   - a `?language=ja` URL parameter,
   - a `language` key in a `configurationId` or `configCID` configuration.

   `ja`, `ja-JP` and `jp` all mean Japanese. `zh`, `zh-CN`, `zh-SG` and `zh-Hans*` mean Simplified Chinese; `zh-TW`, `zh-HK`, `zh-MO` and `zh-Hant*` mean Traditional. Matching ignores case and treats `_` as `-`. Unsupported values are ignored.

3. **A browser language we have.** The first `navigator.languages` entry that is supported and isn't English.
4. **A time zone.** This covers people whose browser is set to English: `Asia/Tokyo` is Japanese, `Asia/Shanghai` Simplified Chinese, and `Asia/Taipei` and `Asia/Hong_Kong` Traditional Chinese (`TIME_ZONE_LANGUAGES` in `language.ts`).
5. **English.**

Detection uses only the browser; there is no network lookup. The language survives the Google, Apple and Tesla sign-in round-trip through the flow snapshot (`src/utils/flowSnapshot.ts`).

Known limits:

- The email with the sign-in code and error text from DIMO's servers are English.
- The Google, Apple and Tesla sign-in pages use their own language settings.
- The developer console's configurator can't set `language` yet. Until it can, apps using `configurationId` links can add `language` to the configuration through the API, or pass `?language=ja`.

## Adding or changing copy

1. **Add the key to `en.ts`, then the same key to `ja.ts` and `es.ts`.**
   - Keys are flat, dot-namespaced and snake_case (`share.cta_share`), as in DIMO Driver.
   - `ja.ts` and `es.ts` are typed against `en.ts`, and `src/i18n/__tests__/locales.test.ts` fails when a key, a `{{param}}` or a `<tag>` is missing in any language.
2. **Write whole sentences.** Don't build copy from fragments ("Share" + count + "vehicles"); word order differs between languages.
   - Pass values as params: `t('common.back_to_app', { appName })`.
   - Plurals use i18next suffixes: `_one` and `_other` in English, `_other` only in Japanese, and `_one`, `_other` and `_many` in Spanish. Pass `count`.
3. **In components, use `useT()`** (it re-renders on a language switch).
   - For copy with links, use `<Trans k="legal.notice" components={{ terms: <a href={…} /> }} />`.
   - Outside React, use `t()` from `src/i18n`.
4. **Keep keys in state, not translated text.**
   - Errors and loading messages are `Text`: a `message(key, params)` or a plain string that is shown as is (server error text).
   - `ErrorMessage`, `Loader` and `ErrorScreen` translate when they render, so a language switch mid-flow updates everything.
5. **Keep protocol strings English.**
   - Error reasons posted to the app (`sendErrorToParent`), payload keys (`sharedVehicles`, `revokedVehicles`…), event types, the on-chain license alias and logs are part of the developer API.
   - Thrown errors keep an English `message` for Sentry and carry a code for display (see `GrantUnreadableError.toMessage()`).
6. **Format dates, lists and numbers with `src/i18n/format.ts`.**
   - Never parse a formatted date back. Logic uses the ISO `grantExpiresAt` or unix seconds.
   - Dates shown in the contract are UTC and say so.

Tests initialize English (`src/setupTests.ts`), so English copy can be asserted directly. A key without copy throws in tests.

## Adding a language

1. Add the code to `SUPPORTED_LANGUAGES` and to `normalizeLanguage` in `language.ts`. Add its Intl locale to `INTL_LOCALES` (`format.ts`) and its collation to `COLLATION` (`utils/countries.ts`; Chinese uses `zh-Hans-CN` for pinyin and `zh-Hant-TW` for stroke order). Add time zones that imply it to `TIME_ZONE_LANGUAGES`.
2. Add `locales/<code>.ts`, typed as `LocaleResources`, and register it in `src/i18n/index.tsx`.
3. Add its plural forms. The locales test reads them from `Intl.PluralRules`.
4. Add its native name to `NATIVE_NAMES` in `LanguageSwitcher.tsx`.
5. If its script isn't covered by Euclid Circular A, add a system font stack for `:lang(<code>)` and `[lang='<code>']` in `src/index.css` (Chinese has one per script, `zh-Hans` and `zh-Hant`). Name the Linux and ChromeOS families too (for Japanese, `Noto Sans CJK JP`): left to `sans-serif`, those systems can draw the text with another script's font.
